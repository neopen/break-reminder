已经配置了 GitHub Actions 自动构建，因此正式发布版本不需要手动上传 Windows、macOS、Linux 安装包。

**核心流程：更新版本号 → 提交代码 → 创建 Git Tag → 自动构建 → 自动发布 GitHub Release。**

## **1. 修改 package.json 版本号**

例如准备发布 `0.5.9`：

```json
{
  "name": "HealthClock",
  "version": "0.5.9"
}
```

注意：

- `package.json` 中版本号不带 `v`。
- Git Tag 使用 `v0.5.9`。
- `package-lock.json` 也要同步更新。

执行：

```bash
npm install --package-lock-only
```

## **2. 提交正式发布代码**

先确认本地构建和测试通过：

```bash
npm ci
npm run build
npm run verify:build
npm run dist:win
```

然后提交代码：

```bash
git add .
git commit -m "chore: release v0.5.9"
git push origin main
```

如果你使用其他开发分支，应先合并到 `main`，再发布。

## **3. 创建并推送 Git Tag**

```bash
git tag v0.5.9
git push origin v0.5.9
```

自动触发

这一步会触发：

```yaml
on:
  push:
    tags:
      - "v*.*.*"
```

## **4. GitHub Actions 自动执行**

进入 GitHub 仓库：

```
https://github.com/neopen/break-reminder/actions
```

工作流执行顺序：

1. **推送 Tag：v0.5.9**
2. **Windows** 安装包、便携版
3. **macOS**   DMG、ZIP
4. **Linux**   DEB、RPM、AppImage
5. **汇总所有平台构建产物**
6. 自动发布    **GitHub Release v0.5.9**

## **5. 检查 GitHub Release**

打开：	[HealthClock Releases](https://github.com/neopen/break-reminder/releases?utm_source=chatgpt.com)

正常情况下会看到：

| 平台    | 文件         |
| ------- | ------------ |
| Windows | Setup.exe    |
| Windows | Portable.exe |
| macOS   | .dmg         |
| macOS   | .zip         |
| Linux   | .deb         |
| Linux   | .rpm         |
| Linux   | .AppImage    |

同时会自动生成 Release Notes。

## **6. 如果发布失败怎么办？**

根据失败位置处理：

| 失败位置     | 处理方法                          |
| ------------ | --------------------------------- |
| Windows 构建 | 检查 npm 依赖、原生模块           |
| macOS 构建   | 检查架构、签名及原生模块          |
| Linux 构建   | 检查系统依赖、RPM 工具            |
| Release 发布 | 检查 `contents: write` 权限       |
| 版本校验     | 检查 Tag 与 package.json 是否一致 |

如果构建失败，修复代码后，不建议重复使用同一个正式 Tag 发布。更稳妥的做法是修复后增加补丁版本，例如 `v0.5.10`。

## **7. 以后每次发布只需要执行这几条命令**

假设下一次发布 `0.6.0`：

```bash
# 1. 修改 package.json 版本号为 0.6.0

# 2. 同步 lock 文件
npm install --package-lock-only

# 3. 提交
git add .
git commit -m "chore: release v0.6.0"
git push origin main

# 4. 创建正式 Tag
git tag v0.6.0
git push origin v0.6.0
```

**补充一个重要提醒：** 你目前的工作流使用 `workflow_dispatch` 手动触发，但版本校验依赖 Tag。如果手动运行时选择 `main`，通常无法通过版本校验。正式发布直接推送 Tag 就可以，不需要手动运行工作流。

另外，你的 macOS 版本目前尚未配置代码签名和公证，正式向普通用户分发前建议补上这部分。
